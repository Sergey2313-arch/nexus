# Security Scanner

Dashboard → «ПРОВЕРИТЬ СИСТЕМУ». Выполняется восемь этапов с отменой и лимитом 45 секунд на сбор данных каждого этапа. Результаты и итог записываются в существующий SQLite Logbook, категория Security.

Проверки: процессы, команды автозагрузки Win32_StartupCommand, автоматические службы, до 200 EXE в корне Temp, установленные TCP-соединения, состояние и обнаружения Defender, брандмауэр/UAC, корреляция одинаковых файлов между источниками.

Для файлов в Temp/AppData проверяется Authenticode средствами Windows. Невалидная подпись в таком каталоге — повод для проверки, не доказательство вредоносности. Пути недоступных защищённых процессов могут отсутствовать; сложные команды запуска и пути драйверов поддерживаются не полностью. Планировщик заданий, рекурсивное сканирование дисков, SFC/DISM и аппаратный Health Score пока не реализованы. Сканер не меняет настройки, не удаляет файлы, не запускает их и не отправляет данные в сеть.

Риск 0–100 отражает сумму обнаруженных признаков (Warning +10, Critical +30, максимум 100); это не вероятность заражения. Недоступность этапа видна отдельно и делает итог частичным. Историческое незавершённое действие Defender требует проверки актуального состояния в журнале защиты.

## Проверка на Windows

1. Собрать Debug x64 с .NET 8 / Windows App SDK в Visual Studio либо командой из CI.
2. Запустить сканирование без повышения прав: приложение остаётся отзывчивым, этапы с отказом доступа отмечаются недоступными.
3. Отменить сканирование, повторить его, закрыть окно во время проверки: дочерний PowerShell завершается.
4. Сопоставить Defender и брандмауэр с «Безопасностью Windows», находки — с реальными путями файлов.
5. Проверить запись итогов в Logbook / Security. Не отключать защиту специально для теста.

Полная сборка и runtime-проверка требуют Windows. CI добавлен для сборки на windows-latest.
